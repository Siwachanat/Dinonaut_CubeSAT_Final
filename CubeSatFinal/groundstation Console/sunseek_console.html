Kick log angle moved by each kick, measured from EST_ANGLE

#TimeModeDirWheelAngle beforeAngle afterΔθΔθ +3 sCycle

A kick is detected when the wheel leaves BIAS and logged 0.5 s after it is back. Δθ +3 s is filled in only when no other kick followed. If it is much smaller than Δθ, the body creeps back after each kick (drag-type friction), and momentum kicks will struggle to converge on this rig. Needs the ADCS stream (4 Hz), so Δθ is approximate. Characterise in AUTO: set a target 10–20° away and watch the kicks.

Manual wheel (MANUAL + MOMENTUM)

In MANUAL there is no automatic recovery: the wheel stays at bias + delta until you send RW_BIAS again (an abrupt step). RW_CMD deltas add to the current target, not the bias.

Final angle and next set angle

No picture is used here. Final is the spacecraft's own angle (TARGET − POINTING_ERROR in the ADCS telemetry), averaged from 1 s before the hold was complete until the capture was done. Error = final − target (+ = ended to the right of the target). Next set is the angle to send next time so that the spacecraft ends on the target: set angle − error. Apply next angles stores it as an offset; the target stays as you typed it, and Upload sends target + offset. This corrects where the control loop comes to rest. It cannot see an error of the sensor itself (compass calibration, zero datum): for that, look at the pictures after the mission and type the offset by hand. The correction is right only if the same error repeats, so keep the same targets in the same order.
