5. **Sun angle: regional-round method** (2026-10-07, marked `[Team]`; flash 55.6 % -> 56.1 %,
   735,860 B on pioarduino 55.03.312-1). `Module_SunSensor.h` rewritten; selected by
   `SUN_ALGORITHM` in `Config_Sensor.h`:
   - `1` (now the default): averaged counts -> LDR conductance `G = c/(C_vcc - c)` ->
     `X = ln(G_L/G_R)` -> ratio table. Lamp brightness and distance cancel in X. Past the
     edge of the ratio zone (a cell below its darkness threshold, or X off the table) the
     angle is read from the level of the lit cell, corrected by a brightness reference that
     is learned continuously inside the ratio zone (`ln(G_L+G_R)` against the table,
     `SUN_AMP_ALPHA`). Tables: new `include/Config_SunCal.h`, generated by
     `python3 tools/suncal_fit.py <sweep.csv>` (reads the console's Sun-cal CSV).
     Current tables are from the 6 Oct 10-degree notebook sweep
     (`tools/suncal_2026-10-06.csv`): ratio zone -50..+40, level branch to -70/+70.
   - `0`: organisers' raw-count NDV -> `estimateSunAngle()` (TEAM AREA), as before.
   - Both: `SUN_OVERSAMPLE` interleaved reads averaged per side (default 16; 1 = organisers'
     single read). Callers within 15 ms share one sample, so telemetry shows what ADCS used.
   - `SUN_SWAP_LR` exchanges the channels in software. The TEAM AREA LUT pasted on 6 Oct
     was written for swapped pins, but `Config_Sensor.h` still had 17/16: with the LDR
     leads as calibrated, SUN_ANGLE ran backwards (0 deg read -36). The LUT is now stored
     for the pins as wired (GPIO17 = L, GPIO16 = R). No pin swap is needed for either mode.
   - Telemetry format unchanged: `SUN_L/SUN_R` = averaged counts, `SUN_NDV` = raw-count NDV
     in both modes. New: `SUN_STATUS` (branch, X, brightness reference, saturation,
     millivolts, `SUN_VCC_COUNTS_EST` for `--vcc-counts`, `SUN_READ_US`), `SUN_REF_RESET`.
     `CAL_STATUS` reports `SUN_ESTIMATOR,TEAM_RATIO_LEVEL,SUN_CAL,<label>`.
   - Check: `python3 tools/hosttest/run.py` compiles the module on a PC (g++) and feeds it
     the sweep: all 15 points read back, board code and fit tool agree on 5000 random
     inputs, algorithm 0 still returns its LUT. Firmware builds with both settings.
     **Not yet run on the board.** Originals: `backup_pre_sunratio_20261007/`.

7. **Relative-yaw EKF and `ADCS_REFERENCE,YAW`** (2026-10-08, `[Team]`; flash 56.1 % -> 56.8 %,
   743,944 B; RAM +184 B). A third ADCS reference next to SUN and MAG. SUN and MAG are untouched:
   the whole firmware was run on a PC before and after the change (fake GY-89, wheel and body) and
   five scenarios (MAG AUTO, SUN AUTO, MAG mission, MOMENTUM MAG, manual + calibration commands)
   gave bit-identical trajectories and telemetry.
   - New `src/Module_YawEKF.h`: 2-state Extended Kalman Filter, state = [yaw, gyro bias].
     Prediction from gyro Z every control cycle (trapezoid between samples); correction from the
     horizontal magnetic field vector `B[cos a, sin a]`, linearised each cycle, only when the
     magnetometer has a new sample. Residuals beyond 3 sigma are not used; if that lasts 1 s the
     heading is re-acquired from the magnetometer. Measurement variance grows when the field
     strength is off its tracked value or the other two gyro axes show swinging. The bias state
     is frozen above 6 deg/s. A gap in sampling over 0.25 s (e.g. `GYRO_OFFSET`) is not integrated.
   - Accelerometer: the bytes `imuReadRaw()` already fetched every cycle are now used (no extra
     I2C traffic). Gravity lies on the rotation axis, so it carries no yaw information; its
     low-passed direction gives `TILT_DEG` and, optionally, tilt compensation of the field
     (`YAW_EKF_TILT_COMP` / `YAW_TILT,ON`). Compensation is refused unless `MAG_SCALE_Z` is
     between 0.5 and 2.0, i.e. unless the magnetometer was calibrated by tumbling in 3-D.
     Today's 3.32 is from a flat turn, so it stays off.
   - Output: relative yaw = estimated heading minus the zero datum, -180..+180 deg, positive =
     rotated right (same sense as SUN_ANGLE and MAG_HEADING). The datum is the boot attitude
     until `YAW_ZERO`. In `ADCS_REFERENCE,YAW`: `SET_TARGET` / `MISSION_TARGET` accept
     -180..+180, the error takes the short way round, the D term and the Momentum "settled"
     test use the gyro rate with the estimated bias removed, and the organisers' filter +
     fusion chain is bypassed (`EST_FILTER_TYPE,EKF_YAW`; `EST_RAW` = magnetometer relative
     heading, `EST_ANGLE` = EKF). The EKF runs in every reference, so it is converged when selected.
   - Telecommands: `ADCS_REFERENCE,YAW` (MANUAL only, like SUN/MAG), `YAW_ZERO` (refused only in
     AUTO on YAW, so the datum can be taken while SUN or MAG holds a target), `YAW_STATUS`,
     `YAW_RESET`, `YAW_TILT,ON|OFF`, `YAW_MAG_SIGMA,<0.5..45>`.
   - Telemetry: `TM,YAW_REL,..,YAW_ABS,..,YAW_MAG,..,YAW_BIAS,..,YAW_SIGMA,..,YAW_INNOV,..,
     YAW_ZEROED,..,YAW_VALID,..` (added to the ADCS stream only in YAW reference); `YAW_STATUS`
     adds `YAW_ZERO_HEADING, YAW_RATE, YAW_SIGMA_BIAS, YAW_INNOV_RMS, YAW_GAIN, YAW_USED,
     YAW_REJECTED, YAW_REACQUIRED` and `YAW_FIELD, YAW_FIELD_REF, YAW_VAR_SCALE, TILT_DEG, ACC_OK,
     TILT_COMP, YAW_MAG_SIGMA, EKF_US, EKF_US_MAX` (EKF_US = measured cost of one step, microseconds).
   - Settings: new `include/Config_YawEKF.h`. Files changed: `Module_ADCS.h` (reference, EKF
     call between the IMU read and the sun read), `Module_Estimator.h` (`estimatorSetExternal`),
     `System_Telemetry.h`, `System_CommandRouter.h`. `Module_IMU.h` and all other Config files
     are unchanged.
   - Checks: `python3 tools/hosttest_yaw/run.py` (the module alone against a simulated IMU, next
     to the organisers' estimator on the same data) and `python3 tools/hosttest_yaw/run_loop.py`
     (the whole firmware in closed loop on a PC). Both PASS. **Not yet run on the board.**
     Before AUTO on YAW: turn right by hand -> `YAW_REL` rises smoothly and `YAW_REJECTED` /
     `YAW_REACQUIRED` in `YAW_STATUS` stay put; `EKF_US` well under 1000.
     Previous files: `backup_pre_yawekf_20261008/`.

# T07 v0.1 FIX2 — Telemetry Gate

Root cause fixed:
- `sensorADCSUpdate()` was still called every loop and transmitted
  `sensorSendADCSSnapshot()` periodically even when SUN/MAG/GYRO streams were OFF.
- That ADCS packet contains SUN_ERROR, MAG_ERROR, GYRO_Z and estimator values,
  so Ground Station continued to display changing sensor values.

FIX2:
- Continuous SUN/MAG/GYRO streams remain OFF after boot.
- Continuous ADCS/Estimator telemetry is now also OFF after boot.
- New commands:
  - `TM_STREAM,ADCS,ON`
  - `TM_STREAM,ADCS,OFF`
- `TM_STREAM_STATUS` now reports ADCS state too.
- `TM_STREAM,ALL,ON|OFF` continues to mean Engineering sensor streams
  SUN/MAG/GYRO only; it does not silently enable ADCS telemetry.
- One-shot STATUS/SNAPSHOT commands may still return requested information.
- Sensor acquisition for ADCS remains independent of downlink telemetry.

Expected after boot:
`SUN=OFF, MAG=OFF, GYRO=OFF, ADCS=OFF`
No continuous sensor/ADCS telemetry should be emitted until commanded.

SunSeek T07 v0.1 FIX6 — Estimator Continuous + MA500

Fixes
1) Moving Average 1..500 samples is now represented with uint16_t for:
   - movingAverageWindow
   - ring-buffer count
   - ring-buffer head
   - iteration indices
   This removes the previous uint8_t overflow above 255.

   Therefore enabling/disabling ADCS telemetry does not change the Moving Average

- Moving Average can be characterized while ADCS is MANUAL.
- Window 1: Filtered Angle follows Raw closely.
- Larger windows: progressively smoother response with increasing lag.
- Windows 256..500 are now valid and no longer truncate/wrap.

No controller gains, reaction/momentum laws, BLE protocol, or payload interface
were intentionally changed.

# SunSeek Training Firmware — T05 v0.1

T05 extends the tested T04 OBC/ADCS baseline with the ESP32-CAM payload control plane.

## Wiring

- SunSeek GPIO41 (TX) -> ESP32-CAM GPIO3 / RX0
- SunSeek GPIO42 (RX) <- ESP32-CAM GPIO1 / TX0
- GND -> GND
- UART: 115200 8N1

Do not connect the ESP32-CAM USB/programmer UART and SunSeek UART drivers to the same RX/TX lines at the same time unless the hardware is specifically designed for that arrangement.

## Architecture

Control plane: Ground Station -> BLE -> SunSeek OBC -> UART -> ESP32-CAM

Payload data plane: ESP32-CAM -> Wi-Fi/HTTP -> Ground Station

JPEG data is never forwarded through BLE or OBC UART.

## First hardware test

1. Flash ESP32-CAM Payload Firmware v0.2 and boot it with microSD installed.
2. Flash this T05 firmware to SunSeek v1.3.
3. Connect common GND and the crossed UART wiring above.
4. Connect Ground Station over BLE.
5. Send `PAYLOAD_STATUS`.
6. Expect `ACK,PAYLOAD_STATUS`, followed by `PAYLOAD,STATUS,...` and a flat `TM,...PAYLOAD_IP,...` update.
7. Send `CAPTURE`.
8. Expect `ACK,CAPTURE`, `PAYLOAD,EVENT,CAPTURE_STARTED`, then `PAYLOAD,IMAGE_READY,...` and `TM,...LAST_IMAGE,...`.
9. Use Ground Station Wi-Fi/HTTP Preview Latest to retrieve the JPEG directly from the payload.

## Added T05 telecommands

- `PAYLOAD_PING`
- `PAYLOAD_STATUS`
- `CAPTURE`
- `PAYLOAD_IMAGE_COUNT`
- `PAYLOAD_LAST_IMAGE`

T01-T04 commands are retained from the T04 v0.2 baseline.

# SunSeek Training Firmware — T05 v0.3 Estimation Integration

Baseline: T05 v0.2, preserving the tested BLE TT&C, Reaction Wheel / ADCS,
sensor, Payload UART and Live View paths.

## What is new

A standard estimation layer is inserted between the selected absolute reference
and the existing PD controller:

`SUN/MAG Reference -> optional LPF -> optional Gyro Complementary Fusion
 -> Estimated Angle -> Pointing Error -> existing PD -> existing RW law`

Power-up defaults keep LPF and Fusion **OFF**, so the verified T05 v0.2 control
behavior remains the baseline until the operator explicitly enables estimation.

### Filter parameter

`ESTIMATOR_FILTER,<0..1>`

This is **Filter Strength**, matching the Ground Station UI:

- `0.00` = Fast (alpha = 1.00)
- `1.00` = Smooth (alpha = 0.00)

Internally: `alpha = 1 - FilterStrength`.

### Fusion parameter

`ESTIMATOR_GYRO_WEIGHT,<0..1>`

- `0.00` = filtered absolute reference dominates
- `1.00` = gyro propagation dominates between reference corrections

Magnetometer calculations use wrapped shortest-angle differences so 359° and
1° are treated as 2° apart.

## New TT&C

- `ESTIMATOR_STATUS`
- `ESTIMATOR_LPF,ON`
- `ESTIMATOR_LPF,OFF`
- `ESTIMATOR_FILTER,<0..1>`
- `ESTIMATOR_FUSION,ON`
- `ESTIMATOR_FUSION,OFF`
- `ESTIMATOR_GYRO_WEIGHT,<0..1>`

## New telemetry

- `EST_RAW`
- `EST_FILTERED`
- `EST_ANGLE`
- `EST_LPF`
- `EST_FILTER_STRENGTH`
- `EST_FUSION`
- `EST_GYRO_WEIGHT`
- `EST_VALID`

Ground Station should calculate Static Stability (1 sigma) and dynamic
Estimator Difference from telemetry; these are intentionally not calculated
inside the spacecraft firmware.

## Hardware-test sequence

1. Flash v0.3 and confirm `STATUS`, sensors, RW and Payload Live View still work.
2. Keep LPF OFF / Fusion OFF and verify ADCS behavior matches v0.2.
3. MANUAL mode: enable LPF and test Filter Strength while plotting raw reference,
   filtered reference and estimated angle.
4. Enable Fusion and test Gyro Weight while manually rotating the spacecraft.
5. Test SUN reference in AUTO, first Reaction then Momentum.
6. Return MANUAL; test MAG reference in AUTO, first Reaction then Momentum.
7. Only after the above passes should these settings be treated as a verified
   Estimation Profile.

This package is a hardware-test candidate; it has not been hardware-validated
by this build process.

# SunSeek Training Firmware T07 v0.1 — Integrated Mission Baseline

Purpose: first integrated firmware baseline for Ground Station Operation /
Competition development and hardware testing.

Inherited from T05:
- BLE TT&C
- Reaction Wheel and ADCS
- Sun / IMU sensing
- Standard LPF + complementary gyro estimator
- Payload UART bridge and Live View

New in T07 v0.1:
1. Engineering sensor telemetry is subscription-controlled and defaults OFF.
2. SUN / MAG / GYRO telemetry can be enabled independently.
3. Sensor acquisition is independent of telemetry transmission.
4. Mission Manager baseline supports target sequences, tolerance, hold time,
   PREPARE / READY / START / ABORT and maximum mission duration.
5. Time-limit expiry does NOT auto-abort or auto-stop the reaction wheel.

## Important v0.1 limits

This is intentionally the FIRST T07 baseline, not final mission firmware.

- Momentum PREPARE currently exposes the state transition but does NOT yet use
  characterized angular-acceleration steady-state qualification.
- Mission Manager reaches CAPTURING after tolerance+hold, but automatic payload
  capture -> IMAGE_READY -> next target is intentionally left as the next
  hardware/GS integration step.
- Mission Name, Run ID, observation metadata and image-transfer strategy remain
  primarily Ground Station workflow until their spacecraft-side contract is
  validated.
- Hardware validation is required.
